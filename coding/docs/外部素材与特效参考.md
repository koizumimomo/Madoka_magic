## 一、pixelfx —— 像素特效库（技能特效的主要来源）

| 项 | 内容 |
|---|---|
| 名称 | **pixelfx** |
| 开源地址 | https://github.com/patch-gg/pixelfx |
| 在线画廊 | https://patch-gg.github.io/pixelfx/ |
| 许可 | **MIT**（可商用） |
| 规模 | 官方 README 现写 **244** 个特效，`src/fx/` 下按分类（火焰 / 爆炸 / 冰霜 / 闪电 / 状态 / UI / 拾取物…）组织，早期版本是 232 个 |
| 特点 | **全部由代码生成，没有一张图片**；支持换色、镜像旋转 |

### 仓库结构（换 agent 时直接照这个路径找）

```
src/core/        绘图内核：帧、画笔、粒子、颜色、数学、字体、预览背景
src/fx/          特效本体，按分类目录；_lib.js 是分类内共享代码
src/fx/categories.js   画廊的分类表
tools/           渲染、检查、导出精灵表、新建、检索、本地画廊
gallery/         带 Patch Pixel 字体的静态画廊页面
skills/pixelfx/SKILL.md   Claude Code skill 定义（用它生成新特效）
docs/AUTHORING.md        特效创作契约、工具包、Painter API 与质量清单
docs/CATALOG.md          全量特效目录
```

### 导入方式

```js
import { createFrame, clearFrame, createFx, composite } from "pixelfx";      // src/core/index.js
import * as frostNova from "pixelfx/fx/ice/frost-nova";                      // 单个特效
import { Painter } from "pixelfx/core/painter";                              // 画笔
```

- Node ≥ 18，唯一开发依赖是 `esbuild`。
- 安装：`npm i github:patch-gg/pixelfx`，或**只复制 `src/core` 与需要的特效文件**（零依赖，推荐）。

### 导出与接入游戏

- 导出：**精灵图（PNG）+ JSON**（含 `fps`、`loop`、列数、`pivot`）。
- Phaser 的 atlas 加载器、Godot、Unity 的 Aseprite 导入器都能直接读。
- 每个特效在相同屏幕尺寸下应当与参考作品"比肩"——同样的细节量、光感、"活"感（`docs/AUTHORING.md` 的质量基线）。

### 我们怎么用（待执行）

我们的技能特效打算全部用 pixelfx 做：

1. 选效果 → 用 `tools/` 渲染成精灵图 → 导出 PNG + JSON。
2. 精灵图作为**粒子贴图**接入 Minecraft：`ParticleType` 用 `ParticleEngineType.SpriteSet`（1.20.1 的 `ParticleTypes` 自定义注册路径），
   JSON 里写 `fps` / `list`（每帧 UV）来播放序列帧。
3. 换色：不同魔法少女用不同色相（黑黄 / 琥珀蜜 / 深蓝银白），直接改贴图色调或用材质的 tint。
4. 需要新效果时，用 `skills/pixelfx/SKILL.md` 让 Claude 生成，再按 `docs/AUTHORING.md` 的标准验收。

当前技能图集由 `tools/render-devotion-fx.mjs` 导出。结界入口、出口和半魔女化粒子由 `tools/render-witch-portals.mjs` 导出，参数依次为 PixelFX 工作副本路径和可选的预览 PNG 路径。Forge 端直接播放生成的图集。

## 二、灵灾（Malum）—— 精魂祭坛的参考实现

| 项 | 内容 |
|---|---|
| 名称 | **灵灾 / Malum** |
| 作者 | SammySemicolon |
| 开源地址 | https://github.com/SammySemicolon/Malum （**本机网络访问不到 GitHub，需要的 agent 请自行检索或改用 Modrinth 的 jar**） |
| 许可 | LGPL-3.0 |
| 版本 | 支持 Forge 1.20.1 / NeoForge 1.20.1+ / Fabric / Quilt |
| 主题 | 精魂（Spirit）魔法，"常被疏嫌的禁忌奥术" |
| 百科页 | https://mcmod.cn/class/4712.html |

### 我们要参考的部分：精魂祭坛（Spirit Altar）

Malum 的祭坛用于**精魂灌注（Spirit Infusion）** 仪式，交互方式就是我们想要的那套：

- **右键把物品放上去** → 物品**悬浮在祭坛上方**（自动旋转/漂浮）。
- **再次右键可以把东西按顺序取下来**（按放入的先后次序，一个一个拿）。
- 集齐材料后触发灌注仪式。

> 本地已下载 1.20.1-1.6.7 的 jar 到 `research/malum/`，
> 祭坛的方块实体与渲染器类可以直接反编译对照。
> 用 CFR：`java -jar tools/cfr.jar <jar> --outputdir <dir> --jarfilter "<类名正则>"`。

### 我们的对应实现

我们的**契约祭坛**要对齐这套交互：

| 行为 | 我们目前的实现 | 需要改成 |
|---|---|---|
| 放入材料 | 右键祭坛放入（已有） | 保持，并让物品**悬浮在祭坛上方** |
| 取回材料 | 无 | **右键空手，按放入顺序（FIFO）逐个取回** |
| 渲染 | 目前没有方块实体渲染器 | 需要 `BlockEntityRenderer`：悬浮旋转的物品模型 |
| 仪式 | 用纸右键触发（已有） | 保持 |

## 三、命名与材质做法参考（匠魂 / 神秘领域 / 神化）

用户指定的参照物：**底模 + 专属标记 + 名字带来源**。

| 模组 | 做法 | 用到我们哪 |
|---|---|---|
| **匠魂（Tinkers' Construct）** | 「强力 的 钻石剑」这种「前缀 + 基础物品」命名 | 悲叹之种命名：`悲叹之种 · 零食魔女` |
| **神秘领域（Tetra）** | 装备改造后带自定义标记 | 灵魂宝石上刻该魔法少女的标记文案 |
| **神化（Apotheosis）** | 稀有装备的独立命名与配色 | 每颗宝石专属颜色 + 专属音色 |
| **灵灾（Malum）** | 祭坛悬浮材料 + 逐个取回 | 契约祭坛的交互 |

### 悲叹之种的具体做法（已定）

- 底模：`textures/item/grief_seed.png`（已放，64×64）
- 中央叠加一枚「魔女之吻」标记：**每位魔女一张**，共 **3 张** → `textures/item/tears/kiss_sacrifice.png` / `kiss_take.png` / `kiss_atonement.png`
- 命名：`悲叹之种 · 零食魔女`（或 `零食魔女 的 悲叹之种`）
- 当前代码是「单个悲叹之种物品 + NBT 记录归属」，**贴图区分还没接线**；
  要让 3 种外观真正区分，需要改成 3 个独立注册物品（每种一个 model + 贴图）。
