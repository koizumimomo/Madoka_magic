# 数据驱动架构

> 目标：**加内容不改代码、不重新编译**。
> 凡是能用数据表达的都在 JSON 里；代码只保留「行为」。

---

## 一、数据放在哪

```
src/main/resources/data/madoka_magic/
├─ magical_girls/          一位魔法少女 = 一个 JSON
│  ├─ index.json           清单（jar 兜底加载用）
│  ├─ sacrifice.json       献身（蝴蝶系）
│  ├─ take.json            索取（蜂后系）
│  └─ atonement.json       赎罪（蓝刺芹系）
└─ spells/                 一个技能 = 一个 JSON
   ├─ index.json           清单
   ├─ butterfly_slash.json …（17 个：12 主动 + 5 被动）
```

加载顺序：

1. **jar 兜底**：模组构造时从自己的 jar 里读（读 `index.json` 清单）——
   保证数据生成、客户端标题界面等没有服务器的环境也有数据。
2. **资源包重载**：服务器启动时 `AddReloadListenerEvent` 触发，
   从数据包目录 `data/madoka_magic/magical_girls/`、`data/madoka_magic/spells/` 重新读，
   **同名文件会被资源包覆盖** —— 所以整合包可以直接改数值、配色、图标。

> ⚠️ 1.20.1 的 `AddReloadListenerEvent` 是 **Forge 总线**事件（它没实现 `IModBusEvent`），
> 用 `@Mod.EventBusSubscriber(bus = Bus.MOD)` 会被 Forge 直接拒绝；
> 正确写法是照 Curios 那样在主类构造里
> `MinecraftForge.EVENT_BUS.addListener(MadokaDataLoaders::addReloadListeners)`。

## 二、魔法少女 JSON 字段

```json
{
  "name": "献身",
  "translation_key": "madoka_magic.magical_girl.sacrifice",
  "classification": "献身型",
  "role": "持续输出型",
  "primary_color": "#F2C14E",
  "secondary_color": "#111014",
  "element": "butterfly",
  "school": "holy",
  "mana_max": 140,
  "tone": "decisive",
  "damage_dealt": 1.10,
  "damage_taken": 1.10,
  "taint_rate": 1.20,
  "mana_gain": 1.05,
  "contract_material": "madoka_magic:black_tulip",
  "witch_dimension": "madoka_magic:witch_sacrifice",
  "skills": ["butterfly_slash", "tulip_burst", "pollen", "blossom", "wither"],
  "passives": ["devotion_wing", "obsession", "ember"],
  "planned_skills": []
}
```

| 字段 | 作用 |
|---|---|
| `name` / `translation_key` | 显示名（翻译优先，缺失时回退 name） |
| `classification` / `role` | 分类与战斗定位（界面与文档用） |
| `primary_color` / `secondary_color` | 配色：宝石、HUD、粒子、确认界面 |
| `element` | 主元素标识（butterfly / honeycomb / eryngium） |
| `school` | 联动的 Iron's 学派 id（**没有铁魔法时这个字段无意义**） |
| `mana_max` | 该魔法少女的魔力总量上限 |
| `tone` | 确认界面文案语气：decisive / casual / pressed |
| `damage_dealt` / `damage_taken` / `taint_rate` / `mana_gain` | 四条属性倍率 |
| `contract_material` | 契约材料物品 id → **材料决定这份契约属于谁** |
| `witch_dimension` | 该魔女专属维度的 id |
| `skills` / `passives` | 她的技能 id |
| `planned_skills` | 还没实现的技能（仅文档用，代码不读） |

> 加一位新魔法少女：写一个 JSON + 在 `index.json` 里加一行 + 建她的契约材料物品 + 建她的维度 JSON。
> **不需要改任何 Java 代码。**

## 三、技能 JSON 字段

```json
{
  "type": "madoka_magic:butterfly_slash",
  "active": true,
  "name_key": "spell.madoka_magic.butterfly_slash",
  "desc_key": "spell.madoka_magic.butterfly_slash.desc",
  "icon": "madoka_magic:textures/gui/spells/butterfly_slash.png",
  "cooldown": 5,
  "mana_cost": 8.0,
  "taint_on_cast": 0.3,
  "unlock_level": 1
}
```

- `type` 指向**效果实现**（代码里注册）。找不到实现时会打警告并跳过该技能。
- `active` = true 进轮盘；false 是被动。
- 冷却、魔力消耗、污染、解锁等级全在 JSON，改数值不用编译。

### 加一个技能

1. 写 JSON（照抄一个改改）。
2. 如果需要**新行为**，在 `spell/MadokaSpellEffects.java` 里加一个方法并注册：

```java
SpellEffects.registerActive("madoka_magic:my_new_spell", MadokaSpellEffects::myNewSpell);
```

3. 在 `index.json` 里加一行。

### 加一个被动

1. 写 JSON，`"active": false`（被动不进轮盘）。
2. 实现一个 `SpellEffects.PassiveEffect` 并注册。可用的钩子（都是 default 空实现，按需覆写）：

```java
apply(ServerPlayer)                                  // 获得被动时
remove(ServerPlayer)                                 // 失去被动时
onDealDamage(ServerPlayer caster, LivingEntity target)  // 造成伤害时（献身之翼挂蝴蝶标记）
onKill(ServerPlayer caster, LivingEntity target)        // 击杀时（执念叠层）
onTakeDamage(ServerPlayer victim, LivingEntity attacker, float amount)  // 挨打时（罪之刻印记罪责）
```

```java
SpellEffects.registerPassive("madoka_magic:my_passive", MY_PASSIVE);
```

3. 在对应魔法少女 JSON 的 `passives` 里加 id（**被动按角色过滤**，不是全局生效），
   并在 `index.json` 里加一行。

> 被动不需要解锁等级：只要角色带着它，事件钩子就会触发。
> 需要"常驻数值"的被动（余晖）不占钩子——在伤害结算处查值即可，见 `spell/MadokaPassives.java`。

## 四、哪些东西仍然是代码（故意的）

| 内容 | 原因 |
|---|---|
| 技能**行为**（伤害、控制、位移、特效） | 行为要用 Java 写；能用资源包配的部分已经放进 JSON 了 |
| 祭坛方块实体、渲染器 | 交互逻辑 |
| 轮盘界面的数学（极角 → 格子） | 通用算法 |
| 魔女/化身实体 | 需要 AI 与状态机 |
| 属性注册（纯度/魔力/因果/强度） | 数量少、注册期必须固定 |

## 五、校验

启动时日志会打印：

```
[madoka_magic] loaded 3 magical girl(s) and 17 spell(s) from jar
```

如果数量不对，先看 `docs/资源清单.md` 与 JSON 是否漏加 `index.json` 里的条目。
