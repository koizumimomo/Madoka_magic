# 成就条目

2026-11-27。数据在 `data/madoka_magic/advancements/*.json`，语言键前缀 `advancements.madoka_magic.<id>.title/.description`。

1.20.1 的自定义触发器走 `CriteriaTriggers.register(...)`，不经过注册表，也不需要 codec。所以本模组自己有六个触发器，类在 `io.madoka.magic.advancement`：

| 触发器 | 发放点 |
| --- | --- |
| `madoka_magic:become_magical_girl` | `PlayerTransformation.toggle`，签约后第一次变身 |
| `madoka_magic:half_witch` | `PlayerTransformation.beginHalfWitch` |
| `madoka_magic:despair` | `PlayerTransformation.inheritWitchPower`，击杀自己魔女化而来的魔女 |
| `madoka_magic:full_purity` | `MadokaMath.addProgression`，纯度触顶 |
| `madoka_magic:star_map` | `PassiveTree.learn`，该主题的节点全部至少一级 |
| `madoka_magic:witch_hunter` | `PlayerEvents.onMobDeath`，击败数达到 22 个结界主题 + 魔女之夜 |

`MadokaCriteria.bootstrap()` 在 mod 构造里调一次，保证数据包加载前注册完成。

## 三、还要验的

**舞台落幕的 NBT 判据。** `MadokaWitchEntity` 把主题写在 `theme` 键上，实体判据写的是包含匹配。魔女之夜会不会在死亡瞬间清掉主题，进游戏打一只才知道。

**魔女猎手的计数口径。** 现在按「已击败主题数 ≥ 22 个结界 + 魔女之夜」。如果以后加了不带结界的外来魔女，这个数字要跟着改。

**星图全部点亮的门槛。** 判定是「该主题所有节点至少一级」，不是「点满级」。如果设计上要的是点满，改 `PassiveTree.allLit` 里的 `< 1` 为 `< node.maxRank()`。

## 四、怎么测

```
/advancement grant @s only madoka_magic:desk
/advancement revoke @s only madoka_magic:desk
```

成就解锁后不会因条件消失回收，重测先 revoke。自定义触发器也可以临时手动发：

```
/advancement grant @s only madoka_magic:half_witch
```
