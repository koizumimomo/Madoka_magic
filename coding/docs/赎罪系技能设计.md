## 零、定位

| 项 | 内容 |
|---|---|
| 名称 | 赎罪 |
| 分类 / 定位 | 赎罪型 · 反击型 |
| 主元素 | 蓝刺芹（Eryngium） |
| 配色 | 深蓝 `#1B2A4A` + 银白 `#C8CEDA` |
| 契约材料 | 蓝刺芹 `madoka_magic:eryngium` |
| 魔力总量 | 120 |
| 伤害 / 受伤 / 污染 / 魔力获取 | +0% / +0% / +0% / +0%（中性数值，强度来自技能循环） |
| 核心资源 | **罪责**（挨打攒出来的） |
| 情绪曲线 | 压抑 |

**一句话**：她的强度来自**承受**，而不是制造——别人欠她的越多，她越强。

**完整循环**

```
被敌人打 → 罪之刻印自动记账（罪责上涨）
  ├─ 荆棘之拥：定身+持续伤害，主动攒罪责；打被束缚者会被反刺
  ├─ 无法偿还的约定：只吃它 30% 伤害，攒约定池，到期一口气还回去
  └─ 赎罪之刃：锁定罪责最高的敌人，消费罪责爆发（自己也吃反噬）
```

三个技能共用同一种资源（罪责），构成"挨打 → 记账 → 偿还"的闭环。
罪责**不会枯竭**，但需要有人打她——没敌人时它就是一个普通魔法少女。

## 一、主动技能（3 个）

轮盘（R 键）里的顺序按解锁等级排。数字键可直选。

### 荆棘之拥 · `thorn_embrace`

| 项 | 值 |
|---|---|
| 解锁 | Lv1 |
| 冷却 / 魔力 | 12 秒 / 18 |
| 范围 | 半径 5 格，最多 8 个目标 |
| 持续 | 6 秒 |
| 持续伤害 | 每秒 2.0（走统一伤害公式） |
| 定身 | 每 tick 清零水平速度 + 打断寻路 + 缓慢 IV |
| 打断 | 中止模组魔女未出手的蓄力。束缚期间，模组魔女与玩家无法发动新技能，正在生效的攻击段继续结算。 |
| 反刺 | 攻击被束缚者的人，承受自身伤害的 30%（真实伤害，上限 6 点） |

**设计意图**：C 的束缚技。同时是**主动攒罪责**的手段——荆棘的持续伤害也记入罪责，
所以 C 不必干等挨打。

> 实现：`spell/ThornTracker.java`（静态列表 + 每 tick 结算）
> 反刺结算在 `TaintEvents#onLivingDamageThorns`；反刺有递归防护（两个被束缚的敌人互相打不会无限反弹）。

### 无法偿还的约定 · `unpayable_promise`

| 项 | 值 |
|---|---|
| 解锁 | Lv3 |
| 冷却 / 魔力 | 24 秒 / 15 |
| 目标 | 准星指向的**眷属**（不能对玩家用，第九章第 3 条已拍板） |
| 立约条件 | 目标必须**已经欠你罪责**（它得先打过你） |
| 持续 | 10 秒 |
| 减伤 | 它对你造成的伤害只生效 **30%**，其余进约定池 |
| 返还 | 到期且目标活着、在 32 格内 → 池中伤害**一次性**还给它 |
| 失败 | 目标死亡 / 逃出 32 格 / 玩家死亡 → 约定失败，池子清空 |

**设计意图**：C 的核心机制，也是"无法原谅自己，却不愿放弃那个人"的直译：
她不能报复（不原谅），但也不放手（不愿放弃），所以只能把伤害记下来，到期原样奉还。

**立约条件**为什么是"目标欠你罪责"：设计 §C-1 写明罪责是"供赎罪之刃和无法偿还的约定消费"
的资源，但 §C-4 没写具体消耗。实现时的解读是——**不扣罪责，但必须以罪责为前提**
（"他先欠你，才谈得上偿还"）。这条已记入 §五 偏差表。

> 实现：`spell/PromiseState.java`；状态存在玩家数据里（`promiseTarget / promiseEndTick / promisePool`），
> 每次结算现扫附近实体按 UUID 找目标，不依赖跨存档的实体引用。

### 赎罪之刃 · `redemption_blade`

| 项 | 值 |
|---|---|
| 解锁 | Lv5 |
| 冷却 / 魔力 | 20 秒 / 16 |
| 目标 | 半径 16 格内**罪责最高**的敌人（"欠她最多的那个"） |
| 基础伤害 | 6.0 + 1.0 × 消费的罪责量（走统一伤害公式） |
| 处刑 | 结算时**无视同阵营 50% 减免**（跨阵营结算） |
| 反噬 | 玩家承受消费量的 **20%** 真实伤害 |
| 前置 | 目标罪责 ≥ 1.0，否则不触发 |

**设计意图**：她的输出完全来自"别人欠她的"。反噬让"用罪责攻击"本身带有自伤——
爱与罪恶的兑换。

> 实现：`MadokaSpellEffects#redemptionBlade` + `spell/GuiltMark.java`。
> "处刑"通过 `spell/DamageContext#runBypassingSameFaction` 标记，`TaintEvents` 乘阵营减免前查这个标记
> ——这正是 `框架层说明 §3.2` 推荐的"可查询的伤害上下文"，没有在阵营层给单个技能写 if-else。

## 二、被动技能（3 个）

### 罪之刻印 · `sin_mark`（事件型，C 专属）

任何敌人对你造成伤害时，自动在**它身上**留下罪责标记。

| 项 | 值 |
|---|---|
| 记录内容 | 施暴者、累计伤害、已结算次数（NBT 在敌人身上） |
| 上限 | 目标最大生命的 **50%** |
| 记账口径 | 实际伤害（`LivingDamageEvent` 的 `getAmount()`，已过护甲/抗性） |
| 按玩家分开 | 是（多人游戏里两位赎罪系玩家互不干扰） |
| 视觉 | 施暴者身上浮现银白刻印粒子，罪责越高粒子越多 |

**罪之刻印不占主动位**，是事件型被动：C 的三个主动全部消费同一份罪责。

> 实现：`spell/GuiltMark.java`（账本）+ `spell/AtonementPassives.java`（被动实现）
> 被动钩子 `PassiveEffect#onTakeDamage` 是本轮给 `SpellEffects` 新加的扩展点（默认空实现，其它系不受影响）。

### 执念 · `obsession` / 余晖 · `ember`

与献身系共用（`spell/MadokaPassives.java`）：击杀叠层 +8%/层，污染每 10 点 +2% 伤害。
"余晖"和 C 的"承受"主题也契合：越接近魔女化越强。

## 三、代码结构

| 文件 | 职责 |
|---|---|
| `spell/GuiltMark.java` | 罪责账本：记账、读取、消费、找最高、HUD 总量 |
| `spell/AtonementPassives.java` | 罪之刻印被动（事件 + 视觉） |
| `spell/ThornTracker.java` | 荆棘之拥：束缚、定身、持续伤害、反刺参数与递归防护 |
| `spell/PromiseState.java` | 无法偿还的约定：立约、减伤入池、到期返还、失败清空 |
| `spell/DamageContext.java` | 伤害上下文：处刑用的"无视同阵营减免"标记 |
| `spell/MadokaSpellEffects.java` | 三个主动技能的行为实现 + 新被动注册 |
| `spell/SpellEffects.java` | `PassiveEffect` 新增 `onTakeDamage` 钩子 |
| `event/TaintEvents.java` | 约定减伤、荆棘反刺、罪责记账入口、死亡清理 |
| `event/PlayerEvents.java` | 每秒驱动约定。荆棘由 `ThornTracker` 按维度逐 tick 结算。 |
| `data/PlayerMadokaData.java` | 约定状态（目标 / 到期时间 / 池） |
| `network/MadokaNetwork.java` | `SyncState` 新增罪责总量、约定剩余时间、约定池（协议版本 2） |

**数据驱动**：3 个主动 + 3 个被动的元数据（冷却 / 魔力 / 污染 / 解锁等级 / 图标）
全部在 `data/madoka_magic/spells/*.json`；换数值不用编译。

## 五、与设计文档的偏差与解读

| # | 事项 | 说明 |
|---|---|---|
| 1 | **约定不消耗罪责，但以罪责为前提** | 设计 §C-1 说罪责"供赎罪之刃和无法偿还的约定消费"，§C-4 没写消耗多少。实现取"立约条件 = 目标已欠罪责"的读法，不扣数值。若后续要改成扣罪责，只需在 `unpayablePromise` 里加一次 `GuiltMark.consume`。 |
| 2 | **赎罪之刃反噬按 20% 计** | 设计原文"承受等量的反噬伤害（小额，但是真的）"。"等量"与"小额"矛盾，按小额取 20%。 |
| 3 | **约定"目标死亡"算失败** | 设计同时写了"目标死亡时返还"和"死亡未结算则池子清空"。取后者（C 的叙事是"承诺落空就白挨打"）。 |
| 4 | **约定池上限 200** | 设计没写上限。加安全阀，防止极端情况一次返还秒杀 Boss。 |
| 5 | **荆棘定身是"每 tick 清零水平速度 + 打断寻路 + 缓慢 IV"** | 1.20.1 没有原版"定身"效果，纯靠速度清零。实测能站住，但被击退时会有 1 tick 的位移。 |
| 6 | **荆棘的打断范围** | 打断模组魔女冲锋、剑扫和场地攻击等技能的蓄力。玩家被束缚时无法施放本模组主动技能。凋零沿用原版 AI。 |
| 7 | **反刺是 30% 而非"伤害的一部分"的精确值** | 设计没给数值，取 30% + 上限 6。两个被束缚的敌人互相打时有递归防护（只弹一层）。 |
| 8 | **约定线/荆棘是服务端粒子** | 多人游戏里别的玩家也能看见；但跨维度时粒子可能发到错误的维度（已知小瑕疵，单人可忽略）。 |
| 9 | **罪责不衰减** | 设计说资源"不会枯竭"，所以没做自然衰减；敌人死亡/despawn 时账本随之消失。 |

## 六、HUD 数据接口（已同步到客户端）

`ClientMadokaState` 新增三个 getter，HUD 可以直接读：

| 方法 | 含义 |
|---|---|
| `getGuiltTotal()` | 附近 16 格敌人的罪责总量（服务端每秒现算） |
| `getPromiseTicks()` | 约定剩余 tick（0 = 没有约定） |
| `isPromised()` | 是否正处于约定中 |
| `getPromisePool()` | 约定池当前积累的伤害量 |

> 网络协议版本从 `1` 升到 `2`（`MadokaNetwork.PROTOCOL`）。客户端/服务端版本不一致时
> Forge 会直接拒绝连接——这是刻意的，比字段错位读出乱数据安全。
