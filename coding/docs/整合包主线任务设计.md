# 魔法记录 · 整合包主线任务设计

2026-11-26。对象是整合包 `D:\mc\.minecraft\versions\魔法记录`（FTB Quests 2001.4.22 + KubeJS 2001.6.5）。
本文给结构、任务清单和文案，可以直接照着建章节。

## 一、先定三条原则

**只讲发生了什么，不讲数值。** 伤害多少、冷却几秒，技能详情页和 JEI 里都有。任务文本再念一遍就是废话。

**奖励给信息、便利和外观，不给战斗力。** 战斗力由纯度和技能解锁推进，那是模组自己的节奏。任务是路标，不是补给站。

**每章结尾要让处境变化，不是数量增加。** 「你现在有一把武器」比「你收集了 3 件物品」有分量。

主线要走的是一个人的选择：为了什么许愿，愿意付多少。所以整条线只有一次分岔（结局），前面都是收窄。

## 四、落地

### 目录

FTB Quests 1.20.1 的章节存在整合包里：

```
config/ftbquests/quests/
  data.snbt
  chapter_groups.snbt
  chapters/<chapter_id>.snbt
  reward_tables/
```

章节文件里一个任务的最小形状（字段名以 2001.4.22 为准，建第一个时对照游戏里导出的模板）：

```snbt
{
  id: "0000000000000C01"
  title: "醒来的房间"
  icon: "minecraft:paper"
  x: 0.0d
  y: 0.0d
  tasks: [{
    id: "0000000000000C11"
    type: "checkmark"
    title: "那张纸"
  }]
  rewards: [{ id: "0000000000000C21", type: "xp", xp: 5 }]
}
```

### 判不了的三件事，用 KubeJS 补

FTB Quests 的任务类型只能看物品、击杀、维度、统计，看不见模组自己的数据（契约性质、污秽、纯度、变身状态）。模组这些值在 `PlayerMadokaData` 的 NBT 里，KubeJS 读得到，直接对着它判。

第一种，签约（`c1_sign`）：玩家签约时，KubeJS 发一条命令把任务标完成。

```js
// server_scripts/quests_contract.js
PlayerEvents.tick(event => {
  const p = event.player
  if (p.level.clientSide) return
  const d = p.persistentData
  // NBT 路径 <THEME_PATH> 必须先从存档里 dump 出来确认，不要照抄
  const theme = <THEME_PATH>
  if (theme && !d.getBoolean('q_signed')) {
    p.runCommandSilent('ftbquests change_progress ' + p.username + ' complete 0000000000000C12')
    d.putBoolean('q_signed', true)
  }
})
```

两处要自己补：`<THEME_PATH>` 是模组在玩家 NBT 里存契约主题的实际路径，从 `saves/<存档>/playerdata/*.dat` 里 dump 一次就能看到；`ftbquests change_progress` 的准确参数以装好的 2001.4.22 为准，先在游戏里敲 `/ftbquests` 用补全确认。

第二种，三系互斥（C1 的三条支线）：签约那一刻，把玩到的那一系标完成，另两系用 `hide` 或 `lock`。FTB Quests 本身没有互斥概念，只能这么硬压。

第三种，污秽和纯度阈值（`c3_30`、`c3_90`、`c5_purity`）：同样在 tick 里读值，到阈值就完成。频率控制在一秒一次，别每 tick 扫。

### 任务类型对照

| 想判的东西 | 用什么 |
| --- | --- |
| 拿到/交付物品 | `item`（一次性教学用 `consume: false`） |
| 打死某只 | `kill` |
| 到过结界维度 | `dimension` |
| 观察状态（污秽、暗角、雷暴） | `observation` 或 KubeJS |
| 模组内部数据（契约、纯度、变身） | KubeJS + `change_progress` |

## 六、别让玩家卡住

**第一位首领固定。** 七位随机抽，第一次抽到武旦或者魔女之夜那种强度的，玩家会死在门口，然后再也没有勇气回去。C4 固定成救济的魔女。

**结界要能重进。** 入口靠污秽满触发，天然可刷。任务不要写「首次」，否则玩家第一次打输就永远缺一个。

**悲叹之种一共 24 点耐久。** 任务里要求「净化 N 次」的，N 不要超过玩家能拿到的种子总量。C5 只要求一次。

**不要强制死亡次数。** 污秽满会死一次，这已经够了。再加「死三次」的任务只会让人烦。

**魔女线放在最后。** 一旦走了，前面的任务全打不了。C10 才分岔。

**联机用 FTB Teams。** 主线任务设成团队共享，否则四个人各刷一遍结界，服务器受不了。

## 七、要拍板的五件事

1. 三系允许换契约吗。允许就做三条支线都能完成（只锁技能），不允许就在 C1 就 hide 掉另外两条。
2. 第一位固定成救济的魔女，同不同意。
3. 咒具没实装，C5 的 `c5_curse` 是留空隐藏，还是先写成「不净化」的行为教学。
4. 凋零的魔女技能（三声丧钟）没实装，C6 那条任务先按现名「凋零」写，还是等技能做完再开章。
5. 任务奖励能不能给「结界地板方块」这类建造材料。给了会鼓励玩家在结界里搭房子，也可能被用来作弊。
