# 踩坑记录

> 记录开发与调试中实际踩到、排查过根因的坑，避免重蹈覆辙。按「症状 → 根因 → 正确做法」格式写。2026-11-22 首次整理（1.0.3 测试反馈轮）。

## 战斗与逻辑

### 1. 变身态「其他武器强制 1 点」不生效
- **症状**：变身（魔法少女/魔女）后手持普通武器仍打出正常伤害。
- **根因**：`ContractWeaponEvents.restrict()` 里把近战判定写成 `getDirectEntity() == null`。但玩家近战 `playerAttack` 伤害来源的**直接实体就是玩家自己**，永远不是 null，判定永假。
- **正确做法**：近战判 `direct == player`；弹射物才是 `direct != null && 命名空间为 minecraft`。
- **教训**：`DamageSource.getEntity()`=责任者（玩家），`getDirectEntity()`=直接执行者（近战=玩家本人，弹射物=箭/三叉戟）。两者别混。

### 2. 魔女技能打不了盔甲架假人（打其他怪物正常）
- **症状**：`enemy()` 明明已加 `ArmorStand`，黑翼斩还是打不中假人。
- **根因**：`targets()` 里手写视线过滤 `level.clip(ClipContext(eye, target.getEyePosition(), ...)) == MISS`。手写射线对盔甲架这类实体不可靠（眼位/碰撞盒差异导致误判遮挡）。
- **正确做法**：与蝶翼斩（`MadokaSpellEffects.slash`）完全一致的目标选取：AABB 范围 + `!(e instanceof Player) && SpellCasting.canAffect(caster, e)`，扇形技能再用 `caster.hasLineOfSight(target)`。盔甲架不是 Enemy，**不能**用 `instanceof Enemy` 过滤。
- **教训**：目标选取代码全 mod 统一抄蝶翼斩这一份经过实测的写法，不要各技能各写一套。

### 3. 「无目标」技能空放返回 NO_TARGET 导致手感差
- **症状**：单体技能（蛊毒、蜂刺、荆棘回响）指向空气时施放失败。
- **正确做法**：找不到目标也返回 `RESULT_SUCCESS`，特效打向 `eye + look × range` 的空气点（`WitchVisuals.sting` / `TakeVisuals.sting` 已加 `Vec3` 重载）；带印记消耗的技能（茧爆、荆棘回响）无印记时只空放特效。
- **教训**：动作类技能一律「可空放」，印记/契约类消耗逻辑与「是否命中」解耦。

## 渲染

### 4. 传送门实体被水挡住（水在门后面也挡）
- **症状**：传送门 swirl 是半透明的，即使水在门**后方**，门也被水色盖住。
- **根因**：实体阶段的 `RenderType.entityTranslucentEmissive` 在半透明地形**之前**渲染，而水等半透明方块最后画、无条件叠在上面（不做逐距离排序）。
- **正确做法**：实体渲染器 `render()` 留空，把绘制挪进 `RenderLevelStageEvent.Stage.AFTER_TRANSLUCENT_BLOCKS`：遍历 `level.entitiesForRendering()` 过滤实体类型，`pose.translate(实体坐标 - 相机 eye)` 后按原局部坐标画，结束手动 `endBatch(各用到的 RenderType)`。参考 `WitchPortalRenderer` / `MagicalGirlCircleVisuals`。
- **教训**：任何要「透出半透明地形」的实体特效都走阶段事件画；阶段事件里自画的 RenderType **必须手动 endBatch**，漏了不显示。

### 5. 粒子淡出依赖 spin != 0
- **症状**：新加的法阵短线条粒子全程不透明，生硬消失。
- **根因**：`DevotionParticle.tick()` 的 alpha 淡出写在 `if (spin != 0)` 分支里；短线条粒子不能旋转（旋转会把线条转歪），spin 传 0 就永远不淡出。
- **正确做法**：传一个极小值 `0.0001F` 当 spin——视觉上不转，但能进淡出分支。
- **教训**：给共用粒子基类加新形态时，先看 tick 里有哪些行为被哪个字段「顺带」控制。

## 结界场景生成（BarrierScenes）

### 6. 旧存档残留布局不被新代码重建（幂等检查误跳过）
- **症状**：新版本明明写了 17×17 出生平台，玩家旧结界里还是一根孤柱。
- **根因**：幂等判定 `center.below().is(CHISELED_STONE_BRICKS)`——旧版本布局**也**会放下这个标记块，于是新版 `apply()` 直接 return，旧布局永久保留。
- **正确做法**：幂等标记必须用**新版布局特有**的方块状态（如「出生平台中央 y=20 是拼贴地板」），并在重建前主动清掉旧残骸（柱子位置上方设空气）。
- **教训**：场景生成的幂等检查=「版本指纹」，改布局必须同步换检查，否则老存档永远停在旧版本。

### 7. 出口门位置偏出竞技场中心
- **根因**：`exitPosition` 硬编码 `death.getX() + 4` 的偏移。
- **正确做法**：遭遇战出口直接传 `run.arena()`（锚点即几何中心），y 用 `level.getHeight(MOTION_BLOCKING_NO_LEAVES, x, z)` 取地表。

### 8. 场景重建的「清理」不能放在幂等 return 之后
- **症状**：出生平台改到柱顶后，旧版贴地平台+断柱残骸仍留在世界里（玩家看到平台在柱子下面）。
- **根因**：清理逻辑写在 `if (已建过) return;` 的**后面**——第二次进结界时幂等判定命中直接 return，清理永远不执行；而旧布局恰好能满足新版幂等判定（中央都是拼贴地板）。
- **正确做法**：`apply()` 结构应为：① 先取 fresh 判定 → ② **无条件清理**出生空域（旧残骸位置，范围要盖住所有历史布局）→ ③ **无条件重建出生结构**（清完把自己重建回来，成本仅 ~1k 方块）→ ④ `if (!fresh) return;` → ⑤ 大场景（主路/竞技场/浮空柱）才走幂等。
- **教训**：幂等跳过的是「生成成本」，不是「自愈责任」。凡是「布局改版后要清旧残留」的清理，必须放在所有 return 之前。

### 9. Curios 自定义槽位要补 `curios.modifiers.<槽位id>` 翻译
- **症状**：咒具 tooltip 下方多一行原始 key `curios.modifiers.curse`。
- **根因**：Curios 会为每个槽位的属性修饰符显示 `curios.modifiers.<id>` 前缀，vanilla 只内置头/胸/腿/脚等原版槽位，自定义 `curse` 槽没有语言条目。
- **正确做法**：zh_cn/en_us 各加 `"curios.modifiers.curse": "装在咒具栏时："` / `"When on the curse slot:"`。

### 10. 拼贴地板只有顶面是拼贴贴图
- **根因**：方块模型用 `cube_bottom_top`，side/bottom 贴了磨制安山岩。
- **正确做法**：`cube_all` 六面同贴图。**注意**：模型改动对存档里已放置的方块不自动生效（客户端只缓存方块状态对应的模型，不会重解析贴图变化？——实际是已放置方块用的就是这个模型，但旧区块客户端重进后才会用新模型；若方块带 BlockState 缓存则需破坏重放）。稳妥说法：让测试时「挖掉重放」验证。
- **教训**：批量改模型用脚本（`.tmp/floor-models-cube-all.py` 的 glob+json 重写模式）。

### 11. 路径/断柱「太整齐」与「太碎」
- **根因**：低频噪声幅度小（±1）且频率低，逐列差异看不出来；但矫枉过正（高频率 /5 + 幅值 2.2 + 逐列哈希抖动 ±1）会让路面碎成一格一跳的散台阶。
- **正确做法**：台阶感来自**低频连续噪声 + 同排（整行）同高**——频率低（/12）、幅值大（2.6），相邻行渐变，落差处自然形成横跨整条路径的整级台阶；不要逐列独立抖动。浮空柱的 bottom/height 哈希区间可以拉大（顶面 y≈10–42）。
- **教训**：「乱」的正确粒度是**段**，不是**列**。地形生成里想做出「人工台阶感」，控制变量在行方向上保持一致。
- 所有随机必须走 `hash(seed, a, b)` 确定性哈希，**不要**用 `level.random`（每次重建结果不同，破坏幂等）。

## 资源与注册

### 12. RegistryObject 在静态初始化器里 .get() → 启动崩溃「Registry Object not present」
- **症状**：装上新 jar 后 mod 构造阶段直接崩（`ExceptionInInitializerError`，`NullPointerException: Registry Object not present: madoka_magic:circle_streak_devotion`），栈顶是 `@Mod.EventBusSubscriber` 类的 `<clinit>`。
- **根因**：`MagicalGirlCircleVisuals` 把 `ModParticles.CircleStreak.DEVOTION.get()` 写在 `static final Map` 里。Forge 的 `AutomaticEventSubscriber` 在 **mod 构造阶段**（注册事件 fire 之前）就 `Class.forName` 加载 `@Mod.EventBusSubscriber` 类 → 静态字段立即求值 → `RegistryObject` 还没注入。
- **正确做法**：RegistryObject 的 `.get()` 只能放在事件触发后才会执行的代码路径（tick/render/构造方法内）。需要查表时用惰性单例：`private static volatile Map<...> styles; private static Map<...> styles() { if (styles == null) {...构建...} return styles; }`，首次渲染时构建（那时注册必已完成）。
- **教训**：`@Mod.EventBusSubscriber` 类的**一切静态字段求值都发生在注册表就绪之前**；静态字段里只放常量、RenderType、ResourceLocation 这类不碰注册表的东西。旧代码的粒子 `.get()` 都在 tick/render 方法体内所以没炸，新代码一「提取成常量」就踩雷。

### 13. 创造物品栏构建索引时 `slot.entity()` 为 null
- **症状**：打开物品栏闪退（NPE）。
- **根因**：Curios `getAttributeModifiers` 在客户端构建搜索索引/tooltip 时 `SlotContext.entity()` 可能为 null，直接 `.level()` 就炸。
- **正确做法**：`entity == null || entity.level().isClientSide` 都按客户端处理（走 `OriginalCurseDefinitions.client(theme)`）。
- **教训**：任何 `SlotContext`/tooltip 路径都要防 entity 为 null。

### 14. 变体贴图/新粒子资源清单（每加一种粒子）
- 贴图 `textures/particle/*.png`（PIL 生成，参考 `.tmp/gen-circle-assets.py`）
- 粒子定义 `assets/<ns>/particles/<id>.json`（列贴图，缺了粒子不显示）
- `ModParticles` 枚举注册 + `DevotionParticle.register` 里注册 provider
- 代码里 `level.addParticle(type, ...)`

### 15. 强制 1 点伤害失效（被后面的倍率又乘回去）
- **症状**：变身态玩家换用其它武器，伤害仍然正常，限制看起来没生效。
- **根因**：限制写在 `LivingHurtEvent` 的 HIGH，先把伤害压成 1；`TaintEvents` 等倍率结算在 NORMAL，随后把 1 点重新乘成实际伤害。
- **正确做法**：限制改到 `EventPriority.LOWEST`，并在 `LivingDamageEvent`（护甲/附魔减伤之后）同样兜底一次，保证最终结果就是 1 点。
- **教训**：任何“改成固定值”的伤害干预都要放在所有倍率/减伤之后，否则会被后续事件覆盖。
