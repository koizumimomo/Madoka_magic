# 框架层说明 · 阵营与眷属可见性

> 最后更新：2026-11-08
> 本文件描述**框架层**的接口契约与扩展点。做新内容（技能、实体、结界）时先读这里。
> 设计依据：`魔法少女技能设计.md` §5（阵营）、`魔法少女小圆主题模组-设计提案.md` §13.5（眷属不可见）。

---

## 一、阵营层

### 1.1 阵营模型

| 阵营 | 成员 |
|---|---|
| **魔女侧**（`Faction.WITCH`） | 魔女实体、半魔女化玩家（化身）、**所有原版敌对生物（眷属）**、魔女召唤物 |
| **魔法少女侧**（`Faction.MAGICAL_GIRL`） | 魔法少女玩家、她们的召唤物与投射物 |
| **中立**（`Faction.NEUTRAL`） | 其余一切（动物、村民、**未签约玩家**……） |

### 1.2 判定顺序

`Faction.of(Entity)`：

```
玩家 → Faction.of(Player)：
    isEverContracted() == false  → NEUTRAL（未签约的普通人，不属于任一阵营）
    已签约                       → MAGICAL_GIRL
    半魔女（未来）                → WITCH

实体 →
    1. 实体类型标签 madoka_magic:faction_witch        → WITCH
    2. 实体类型标签 madoka_magic:faction_magical_girl → MAGICAL_GIRL
    3. EntityType.getCategory() == MobCategory.MONSTER → WITCH
    4. 其余                                          → NEUTRAL
```

**标签优先于分类**：标签是"覆盖层"，供未来的半魔女化身、魔女召唤物、
以及第三方 mod 显式声明归属时使用，不必改代码。

**为什么用 `getCategory()` 而不是硬编码实体 id**：设计提案 §13.5 要求
"用标签覆盖全部敌对生物类型，而不是逐个硬编码"。
`EntityType#getCategory()` 是 1.20.1 官方 API，对所有 mod 的敌对生物都成立，
新增怪物自动归队，零维护成本。

### 1.3 标签文件

```
src/main/resources/data/madoka_magic/tags/entity_types/faction_witch.json
src/main/resources/data/madoka_magic/tags/entity_types/faction_magical_girl.json
```

> ⚠️ 目录名是 **`entity_types`（复数）** —— 这是 Forge 的约定，
> 已核对 forge 自带的 `data/forge/tags/entity_types/bosses.json`。
> 写成 `entity_type`（单数）会**静默失效**：标签读不到，不报错。

### 1.4 伤害减免

在 `TaintEvents.onLivingHurt` 的**最外层**（最后乘）：

```
若 attacker 与 victim 同阵营 → 伤害 × same_faction_damage_multiplier（默认 0.5）
```

放在最后乘，保证「魔法少女打自家眷属只吃一半」对所有伤害来源一致
（普攻、技能、投射物都吃）。

**中立阵营不参与减免** —— `isSameFaction` 要求两边都不是 NEUTRAL。

### 1.5 各组合的实际结果

| 攻击方 → 受击方 | 同阵营？ | 结果 |
|---|---|---|
| 魔法少女 → 原版怪物（眷属） | 否（MG vs WITCH） | **满伤** |
| 魔法少女 → 自己的召唤物 | 是（都 MG） | ×0.5 |
| 魔法少女 → 魔女 | 否 | 满伤 |
| 魔女 → 魔女 | 是（都 WITCH） | ×0.5 |
| 未签约玩家 → 眷属 | 否（NEUTRAL） | **完全免伤**（见 §二） |

> 「魔法少女打原版怪满伤」正是设计 §5.3 的原意：
> 「魔法少女 → 只能打魔女侧（跨阵营满伤）」。
> 原版怪＝魔女眷属＝魔女侧，所以魔法少女打它们是**跨阵营**，不吃减免。

### 1.6 配置项

```toml
[faction]
    # 同阵营伤害减免系数
    same_faction_damage_multiplier = 0.5
    # 未签约玩家附近的眷属是否不生成
    familiars_hide_uncontracted = true
    # 眷属可见性判定半径（格）
    familiar_check_radius = 64.0
```

## 二、眷属可见性

### 2.1 设定

世界里所有敌对生物都是「魔女眷属」。成为魔法少女之前，
玩家**看不见它们，也打不死它们** → 拿不到任何怪物掉落物 →
契约材料只能从箱子里来。

### 2.2 判定口径

**按「是否曾经签约」判定**，不是"当前有没有契约"。

原因：魔女化后契约结束、宝石碎裂，若按"当前未签约"算，
玩家会连怪物都看不见也打不死，游戏没法继续（设计提案 §13.5 第 5 条）。

`PlayerMadokaData.isEverContracted()` 是这个判定的唯一依据。

### 2.3 实现：服务器端不生成

**钩子**：`MobSpawnEvent.FinalizeSpawn` → `setSpawnCancelled(true)`。

Forge 的 patch 会真正阻止实体进入世界，所以**不需要任何渲染 mixin**。

**逻辑**：

```
1. 不是敌对生物 → 放行
2. 刷怪笼（MobSpawnType.SPAWNER）→ 放行（见下）
3. 结构生成（level 不是 ServerLevel）→ 放行
4. 附近有签约玩家 → 放行（契约者对所有人可见）
5. 否则 → 取消生成
```

多人服：只要**任何一名**玩家签约，眷属就在其附近正常生成。

**刻意放行的两处**（都写在代码注释里）：

| 情况 | 理由 |
|---|---|
| 刷怪笼 | 玩家自己布置的产物，取消会让玩家困惑、可能破坏进度。改为靠免伤兜底 |
| 结构生成（遗迹 / 地牢） | `WorldGenRegion` 里查实体不可靠，且取消生成会破坏地牢内容 |

### 2.4 免伤兜底

即使眷属通过刷怪笼或已加载区块存在，未签约玩家也**打不死**它们：

`LivingHurtEvent` → 若攻击者是未签约玩家且受击方是眷属 → `setCanceled(true)`。

这是「打不死」与「拿不到掉落」的根本保证。
没有它，刷怪笼就能刷出契约材料，破坏「材料只能从箱子里来」这条经济规则。

### 2.5 魔女索敌

`MadokaWitchEntity` 只锁定**已签约**玩家（`FamiliarVisibility.canWitchTarget`）——
未签约的普通人看不见魔女，魔女也不去打他们。

### 2.6 本框架刻意没做的事

| # | 事项 | 后果 | 后续方案 |
|---|---|---|---|
| 1 | **延迟入场队列**（Part II §7.2） | 取消生成 = 永久取消，契约者靠近时**不会补生成**，只能等自然刷新 | 记录取消生成的位置到队列，契约者靠近时二次 spawn |
| 2 | **原版怪物的索敌过滤** | 原版怪仍会攻击未签约玩家 —— 玩家看不见却挨打，体验割裂 | 按玩家身份过滤原版 AI（需改 AI 而非事件） |
| 3 | **过渡体验**（Part II §7.3） | 未签约玩家听不到远处战斗声（服务器端不生成 = 没有声音源） | 独立的音效/残影事件，不依赖实体存在 |

## 三、扩展点

### 3.1 让某个实体归属某个阵营

在 `data/madoka_magic/tags/entity_types/faction_witch.json`（或 `faction_magical_girl.json`）
里加一行：

```json
{
  "replace": false,
  "values": [
    "madoka_magic:witch",
    "madoka_magic:half_witch",
    "yourmod:your_entity"
  ]
}
```

标签优先于 `getCategory()`，所以哪怕实体不是 MONSTER 类也能指定归属。

### 3.2 让某个技能无视同阵营减免

**已实现**（2026-11-08，赎罪之刃的"处刑"是第一处用户）：`spell/DamageContext.java`

```java
DamageContext.runBypassingSameFaction(() ->
        target.hurt(level.damageSources().playerAttack(caster), damage));
```

`TaintEvents` 在乘同阵营减免前查 `DamageContext.isBypassingSameFaction()`，为 true 时跳过这一层。
标记是深度计数，嵌套调用也能正确恢复；只允许在**服务端主线程的同步伤害结算**里用
（`hurt()` 会同步触发 `LivingHurtEvent`）。

**不要**在 `TaintEvents` 里为单个技能写 if-else —— 那会让阵营层和技能层耦合。
错爱魔女结界的"传导伤害额外衰减"还没做，届时可以复用同一个上下文思路。

### 3.3 加半魔女化

`PlayerMadokaData` 需要加 `isHalfWitch()` 字段，
`Faction.of(Player)` 加一个分支返回 `WITCH`。

半魔女属于魔女侧 —— 这是「转投魔女线」的核心：
签约 → 单挑魔女 → 契约变魔女之吻 → 自身化半魔女 → 进入魔女侧，
之后与魔女侧同阵营，吃 50% 减免。
