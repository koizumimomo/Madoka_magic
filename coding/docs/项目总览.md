## 一、项目是什么

**《魔法少女小圆》主题的 Minecraft 独立模组**（MC 1.20.1 / Forge 1.4.10 47.4.10 / Java 17）。

核心循环（已定）：

```
签约前（普通人）：怪物＝魔女使魔 → 看不见、打不死 → 零掉落
   ↓ 开箱收集契约材料 → 合成契约 → 确认界面 → 仪式（环绕粒子 3 秒）
获得灵魂宝石（魔法少女身份）
   ↓ 用法术战斗：施法消耗魔力，魔力不足才叠加污染；受击 +3、普攻 +0.2
污秽满 100 → 魔女化警告 → 死亡 → 污染清零，死亡位置开启专属结界传送门
   ↓ 门内是与自己同性质的魔女：独自击杀 → 进入魔女线
     （魔法少女之力化为魔女之力：技能转魔女风格，数值重调）
野外随机出现五色战队、凋零及变形魔女的结界入口
   ↓ 击败任意魔女 → 对应性质悲叹之种 → 右键净化（当前污染 ×50% + 15）
重生后选择：保留魔法少女身份 / 放弃身份（重签契约）
成神线：因果值 ≥ 500 后死亡 → 放弃魔法少女身份 → 立下成神契约 → 成为圆环之理
```

**半魔女化**：已变身的魔法少女在污染达到 60 时可按 G 进入半魔女形态。她沿用现有技能，
启动时清空污染，每消耗 1 点获得 1 秒持续时间。半魔女化期间不会累积污染，到期回到魔法少女形态。魔女功能的当前进度见 [魔女待办](魔女待办.md)。

**变身系统**（2026-11-08 定）：魔法少女与魔女线玩家**平时都是普通人形态**，
数值与普通人一样；按特定按键变身才获得数值与技能。
核心目的：在服务器里**隐藏魔女玩家**——魔法少女击杀魔女玩家也能获得悲叹之种、
提高灵魂宝石纯度。变身体验用**环绕粒子特效（pixelfx）**呈现，
不做变身装备/实体模型（模型成本太高）。

**三位魔法少女**（各自独立性质与分类，不按学派划分）：

| 性质 | 分类 | 定位 | 配色 | 主元素 | 契约材料 | 魔力总量 |
|---|---|---|---|---|---|---|
| 献身 | 献身型 | 持续输出型 | 黑 + 黄 | 蝴蝶 / 郁金香 | 黑色郁金香 | 140 |
| 索取 | 索取型 | 控制掠夺型 | 琥珀 + 蜜 | 蜂巢 / 蜂蜜 | 蜂蜜瓶 | 90 |
| 赎罪 | 赎罪型 | 反击型 | 深蓝 + 银白 + 灰黑 | 蓝刺芹 / 荆棘 | 蓝刺芹 | 120 |

**四个属性**：灵魂宝石纯度（击杀积累，决定等级）、魔力值（施法资源，总量因人而异）、
因果值（成神门槛 500，最多 +20% 数值）、魔法强度（只影响魔法少女和魔女的技能强度：
每 +1% → 技能伤害 +1%、冷却 -1%）。

**使魔对普通玩家无害**：原版怪物都算魔女使魔 → 不会在普通人附近生成、普通人看不见、
也不会主动攻击普通人（无害）。

**伤害公式**：`最终伤害 = (基础 × 纯度增幅 × 因果增幅) × (1 + 魔法强度)`，再乘宝石性质倍率。

1. 名字几乎全部引自**西方文艺/神话/历史中的女性**：歌德与浮士德体系（格蕾琴、苏莱卡、夏洛特）、

## 七、踩过的坑（别再踩）

1. **`AddReloadListenerEvent` 是 Forge 总线事件**（1.20.1 里它没实现 `IModBusEvent`）。
   用 `@Mod.EventBusSubscriber(bus = Bus.MOD)` 会被 Forge 拒绝并抛
   *"takes an argument that is not a subtype of the base type"*。
   正确写法照 Curios：`MinecraftForge.EVENT_BUS.addListener(...)`。
   另外它**只在服务器启动时 fire**，所以我们额外做了从 jar 直接读的兜底。
2. **`.properties` 按 ISO-8859-1 读**：中文必须写成 `\uXXXX` 转义，否则注入 mods.toml 会变乱码。
3. **`processResources` 要显式 UTF-8**：`filteringCharset = 'UTF-8'`，否则模板展开按平台字符集走。
4. **1.20.1 官方映射的坑**：`getName(ItemStack)`（不是 `getHoverName`）、
   `ItemRenderer.renderStatic` 是 8 参数版、`EntityAttributeCreationEvent.put` 要的是
   `AttributeSupplier`、属性创建事件**早于配置加载**（不能在里面读配置）。
5. **GeckoLib 必须钉 Modrinth 版本 id**（`8BmcQJ2H:aC5KMoNg`）：按版本号 `4.8.4` 解析会命中
   另一个 MC 版本的 Java 21 构建，开发环境直接 `NoSuchMethodError`。
6. **铁魔法的 mixin 在开发环境会失效**：它的注解用官方名，但 ForgeGradle 把 refmap 改写成 SRG 名。
   解法是 `jvmArgs '-Dmixin.env.disableRefMap=true'`（注意不是 `remapRefMap`）。
7. **本机连不上 GitHub**（api.github.com 与网页都超时），但 Modrinth 可以。需要上游源码时走
   Modrinth 的 jar（`research/malum/` 就是这么下的）。
8. **删除文件要用 `rm --`**（PowerShell 的 `Remove-Item` 被安全网关拦），且路径里的变量
   不会展开，要写显式路径。
9. **`.cmd` 脚本里不能写中文**：cmd.exe 按系统 OEM 码页（本机 936 / GBK）解码批处理，
   UTF-8 的中文会变成乱码字节，其中部分会被当成命令分隔符，于是出现
   `'xx' is not recognized as an internal or external command`。
   `build.cmd` / `run_client.cmd` 已改为**纯 ASCII**（英文提示），改脚本时保持这一点。
   > 注意 `.properties` / `.java` / `.md` 不受此限，它们是 UTF-8 正常读取，
   > 只有 `.cmd` / `.bat` 有这个码页问题。
10. **改 `SyncState` 字段必须升 `MadokaNetwork.PROTOCOL`**：协议号不一致时 Forge 直接拒绝连接，
    比"字段错位读出乱数据"安全。目前是 `"2"`（赎罪系那轮从 1 升上来的）。
11. **静态 tracker 每 tick 只能驱动一次**：`PollenTracker` / `ThornTracker` 由
    `PlayerEvents#onPlayerTick` 驱动，而该事件是**每个签约玩家各触发一次**。
    多人游戏里必须用 `lastTicked == gameTime` 去重，否则持续伤害会成倍跳。
12. **反刺/反弹要有递归防护**：两个被荆棘束缚的敌人互相攻击时，A 弹 B、B 弹 A 会无限递归。
    用 `ThornTracker.isReflecting()` 只弹一层。
13. **`LivingEntity` 没有 `getNavigation()`**：那是 `Mob` 的方法，需要 `instanceof Mob` 转换
    （1.20.1 官方映射）。
14. **罪责账本记在敌人身上、按玩家 UUID 分开**：NBT 键就是 `uuid.toString()`；
    这样多人游戏里两位赎罪系玩家互不干扰，敌人跨区块/存档重载也不丢。
