## 接手摘要

项目是 Minecraft Forge 1.20.1 的《魔法少女小圆》独立模组，ID 为 `madoka_magic`。当前开发根目录是 `E:\CodexCache\madoka\coding`。献身、索取、赎罪三系已具备祭坛签约、变身、技能、污染、魔女化、结界战斗、奖励与净化循环。十个结界有各自的拼贴地板和天空。魔女之夜在主世界独立登场。现有 JAR 是旧版本的构建产物。

## 常驻要求

- **存放位置**。源码、模型、贴图、生成图、工具链、缓存、测试存档、日志、截图和构建产物都保存在当前工作区 `E:\CodexCache\madoka`。Gradle 缓存用 `.gradle-home\`，临时生成与隔离测试用 `.tmp\`。使用有默认输出目录的工具时，优先配置工作区内的路径。若图像工具自动输出到工作区外，把项目资产迁回工作区，再从工作区引用。
- **代码仓库**。制作人提供了源码与模型的提交地址。[Madoka_magic](https://github.com/koizumimomo/Madoka_magic.git)
- **美术工作流**。新增的像素画、技能图标、粒子、魔法符文和像素装饰用 PixelFX 绘制。现有贴图可直接复用。工作区检出目录为 `.tmp\pixelfx-upstream`，说明在该目录的 `skills\pixelfx\SKILL.md`。结界天空的拼贴底图用内置 imagegen，人鱼天空单独漂动的像素五线谱用 PixelFX。参考图与可编辑模型在 `model\`。
- **模型和命名**。模型使用 Blockbench 与 GeckoLib，运行时几何、贴图、动画分别放入 `assets/madoka_magic/geo`、`textures/entity`、`animations`。保留制作人提供的原始文件。对外模组名为《魔法少女小圆》，现有魔女名以语言文件为准，例如「索取的魔女」和「不幸的罪责」。
- **实现与交付**。技能参数沿用现有数据或 Forge 配置；共用命中逻辑由服务端处理，客户端用同步数据画预警。已有明确指示先以源码和开发客户端验证，打包 JAR 时等制作人安排。优先在隔离测试存档复现，再动正式开发存档。

- **梳妆的魔女**。红茶杯里是戴白色波奈特的黑衣娃娃，可编辑模型在 `model/candeloro.bbmodel`。专属攻击为砸地后消失的蛋糕使魔、刀叉齐射和红茶液渍。原模型在 `model/fork&knife`，行为和判定在 `entity/CandeloroCombat.java`、`DessertFamiliarEntity.java`、`CandeloroCutleryEntity.java` 及 `TeaStain.java`，技能参数在 `witch.candeloro`。
- **模型资源**。人鱼和「不幸的罪责」的可编辑模型分别在 `model/oktavia.bbmodel` 与 `model/atonement_frame.bbmodel`。人鱼车轮、处刑游行人偶、蝴蝶和索取结界的巨型虫茧均已接入对应技能。

## 运行和验证

Minecraft 1.20.1，Forge 47.4.10，Gradle Wrapper 8.14.5，JDK 17.0.20+8。GeckoLib 4.8.4 是必需依赖，JEI、铁魔法和 Curios 属于可选兼容。以下命令验证代码与资源，或在工作区运行开发客户端。

```powershell
Set-Location -LiteralPath 'E:\CodexCache\madoka\coding'
$madokaWorkspace = (Resolve-Path -LiteralPath '..').Path
$env:JAVA_HOME = Join-Path $madokaWorkspace 'toolchains\jdk-17.0.20+8'
$env:GRADLE_USER_HOME = Join-Path $madokaWorkspace '.gradle-home'
$env:TEMP = Join-Path $madokaWorkspace '.tmp'
$env:TMP = $env:TEMP
$env:JAVA_TOOL_OPTIONS = "-Duser.home=$madokaWorkspace -Djava.io.tmpdir=$env:TEMP"
.\gradlew.bat --offline compileJava processResources
.\gradlew.bat --offline -x downloadAssets runClient
```

`-x downloadAssets` 适用于当前工作区已有游戏资源缓存的情况。此前 ForgeGradle 的网络环境检查曾阻塞已缓存依赖的离线验证，复现该问题时可对单次命令追加 `'-Dnet.minecraftforge.gradle.check.certs=false'`。用现有 QA 脚本可把客户端运行目录及测试存档隔离在 `.tmp\`。

在主世界空地可用 `/summon madoka_magic:witch ~ ~1 ~28 {theme:"walpurgisnacht"}` 测试魔女之夜。所有在线玩家都会收到登场提示，实战以曾签约的玩家为战斗目标。

Blockbench 的本地调用器是 `.tmp/blockbench-mcp/blockbench-mcp-plugin-main/headless/call-local.ts`。运行时将 `TEMP`、`TMP`、`TMPDIR` 设到工作区 `.tmp\`，用 `--render-home` 指定 `.tmp/blockbench-render`，将 `npm_config_cache` 设为该目录下的 `npm-cache`。Bun 可用 `BUN_INSTALL_CACHE_DIR`、`BUN_RUNTIME_TRANSPILER_CACHE_PATH` 指向工作区内的缓存子目录。本地调用器会把这些设置传给渲染进程。用同一缓存目录复用已安装的预览依赖。会话中的美术参考图在 `model/references`。

## 独立试玩前评估

子智能体只读复核了现有源码、截图和测试日志。它认为污染在「主动换取半魔女力量」和「累积到满、进入自己的结界」之间形成了有辨识度的选择。首领战已能靠场地预警和反制区分机制，蝴蝶剪纸与人鱼五线谱也使结界容易辨认。当前最明显的落差是已有主题场地与技能的几位首领仍共用本体。若近期开放试玩，优先补清楚祭坛与祈愿材料的游戏内引导，再用最新版本走一轮无指令的新存档流程和双人回归。
